# سامانه جامع مدیریت هنرستان شهید رجایی

سامانهٔ تحت وب مدیریت آموزشی برای یک **هنرستان فنی‌وحرفه‌ای**، شامل مدیریت دانش‌آموزان، ثبت تأخیر، غیبت، موارد انضباطی و تخلف پوششی، مدیریت ادمین‌ها با پرمیشن‌های دقیق (granular) و خروجی PDF/چاپ با جدول‌بندی روزبه‌روز.

> **زبان و فناوری:** PHP خالص (۸+) • MySQL/MariaDB یا SQLite • HTML5 + CSS3 + Vanilla JS • کاملاً **فارسی و RTL** با فونت **وزیرمتن** • **تقویم شمسی (جلالی)** با پشتیبانی API معتبر
>
> **بدون نیاز به Composer، Node.js یا کتابخانه خارجی** — آماده اجرا روی هاست معمولی PHP.

## ۱) پیش‌نیازها

| مورد | حداقل | توضیح |
|------|-------|-------|
| PHP | نسخه ۸.۰ | افزونه‌های لازم: `pdo`، `mbstring`، `json` |
| پایگاه داده | MySQL 5.7+/MariaDB 10.2+ **یا** SQLite 3 | SQLite نیازی به تنظیمات ندارد و برای تست/هاست‌های محدود مناسب است |
| افزونه `pdo_mysql` | — | برای اتصال به MySQL/MariaDB |
| افزونه `zip` | اختیاری | برای خواندن/ساخت فایل‌های **xlsx** |
| افزونه `curl` | اختیاری | برای دریافت تاریخ/ساعت از API معتبر (در نبود آن، تاریخ سیستم استفاده می‌شود) |
| دسترسی نوشتن | — | روی پوشه پروژه (برای `config.php`) و پوشه `data/` |

> صفحهٔ نصب (`install.php`) به‌صورت خودکار همهٔ این موارد را بررسی و با علامت / نمایش می‌دهد.

## ۲) نصب سریع (۳ گام)

### گام ۱ — آپلود پروژه
کل پوشهٔ پروژه را در مسیر دلخواه (مثلاً `public_html/honarestan`) قرار دهید و مطمئن شوید پوشهٔ `data` قابل نوشتن است:

```bash
chmod -R 755 honarestan
chmod -R 775 honarestan/data
```

### گام ۲ — اجرای نصب‌کننده خودکار
مرورگر را باز کنید و آدرس زیر را وارد کنید:

```
https://your-domain.com/honarestan/install.php
```

در فرم نصب:
1. **نام مدرسه** را وارد کنید (در سربرگ گزارش‌ها نمایش داده می‌شود).
2. **موتور پایگاه داده** را انتخاب کنید:
 - **SQLite** — سریع‌ترین راه؛ هیچ تنظیمی لازم نیست (فایل پایگاه داده در `data/honarestan.sqlite` ساخته می‌شود).
 - **MySQL/MariaDB** — برای هاست واقعی؛ هاست، نام پایگاه داده، کاربر و رمز را وارد کنید (اگر پایگاه داده وجود نداشته باشد، سامانه تلاش می‌کند آن را بسازد).
3. **حساب مدیر کل** (نام، نام کاربری، رمز) را مشخص کنید.
4. در صورت تمایل، گزینهٔ **«درج داده نمونه»** را فعال بگذارید (۱۸ هنرجو در سه پایه + رکوردهای نمونه برای تست گزارش‌ها).
5. دکمهٔ **« شروع نصب خودکار»** را بزنید.

پس از پایان، فهرست جداول ساخته‌شده، حساب‌های کاربری و مسیر فایل SQL Dump نمایش داده می‌شود.

### گام ۳ — پاک‌سازی و ورود
1. اطلاعات ورود را در جای امنی ذخیره کنید.
2. فایل `install.php` را **حذف** یا تغییر نام دهید.
3. وارد سامانه شوید: `https://your-domain.com/honarestan/index.php`

## ۳) نصب روی هاست اشتراکی (cPanel)

1. فایل‌های پروژه را در `public_html/honarestan` آپلود کنید (File Manager یا FTP).
2. در **MySQL Databases** یک پایگاه داده و کاربر بسازید و کاربر را به پایگاه داده متصل کنید (ALL PRIVILEGES).
3. از File Manager روی پوشهٔ `data` کلیک راست کنید **Change Permissions** `755` (یا `775`).
4. اگر هاست شما PHP 8 را پیش‌فرض ندارد، از بخش **MultiPHP Manager** نسخهٔ PHP را روی **8.x** بگذارید.
5. `install.php` را اجرا کنید و در فرم، اطلاعات MySQL را وارد کنید.
6. پس از نصب، `install.php` را حذف کنید.

## ۴) نصب دستی با SQL Dump

اگر می‌خواهید جداول را خودتان از طریق **phpMyAdmin** بسازید:

1. در phpMyAdmin یک پایگاه داده با کولیشن `utf8mb4_unicode_ci` بسازید.
2. فایل **`honarestan_mysql.sql`** (که هنگام نصب با SQLite یا MySQL در ریشهٔ پروژه ساخته می‌شود) را **Import** کنید.
 - این فایل شامل ساختار کامل ۱۱ جدول + پرمیشن‌ها + حساب مدیر کل است. رمز پیش‌فرض مدیر: `admin123`
3. فایل `config.php` را بسازید (نمونهٔ زیر) و مقادیر را با اطلاعات هاست خود تطبیق دهید:

```php
<?php
return array (
 'driver' => 'mysql',
 'host' => 'localhost',
 'port' => 3306,
 'database' => 'honarestan',
 'username' => 'db_user',
 'password' => 'db_password',
 'charset' => 'utf8mb4',
 'installed' => true,
 'school_name' => 'هنرستان شهید رجایی',
);
```

4. یک فایل خالی با نام `data/installed.lock` بسازید تا سامانه «نصب‌شده» تلقی شود.
5. وارد سامانه شوید و رمز مدیر را تغییر دهید.

## ۵) حساب‌های کاربری پیش‌فرض

هنگام نصب با گزینهٔ «داده نمونه»:

| نقش | نام کاربری | رمز عبور | دسترسی‌ها |
|-----|------------|----------|-----------|
| مدیر کل (بدون محدودیت) | `admin` | `admin123` | همهٔ قابلیت‌ها + ساخت/حذف ادمین |
| معاون آموزشی | `deputy` | `Deputy@1404` | مشاهده/افزودن/ویرایش دانش‌آموز + ثبت تأخیر، غیبت، انضباط، پوشش + PDF |
| معلم | `teacher` | `Teacher@1404` | مشاهده دانش‌آموزان + ثبت تأخیر و غیبت |
| مسئول انضباط | `discipline` | `Discipline@1404` | مشاهده دانش‌آموزان + ثبت انضباط و پوشش + PDF |
| معاون ارشد (ناظر) | `supervisor` | `Supervisor@1404` | ثبت موارد + **مشاهدهٔ همهٔ سوابق همهٔ کاربران** + PDF (نمونهٔ تفکیک سوابق) |

> **فوراً** پس از نخستین ورود، رمزها را از مسیر «مدیریت ادمین‌ها ویرایش کاربر / تغییر رمز من» تغییر دهید.

## ۶) ساختار فایل‌ها و توضیح هر ماژول

```
/honarestan/
├── db.php لایه زیرساخت: اتصال PDO، توابع کمکی، تقویم شمسی، CSRF، RBAC، قالب UI
├── index.php پنل اصلی: فرم ورود + داشبورد آماری (CSS/JS داخلی)
├── admin.php مدیریت ادمین‌ها و پرمیشن‌های granular (CSS/JS داخلی)
├── students.php مدیریت دانش‌آموزان + آپلود Excel/TXT + جستجو/فیلتر/Pagination
├── records.php ثبت تأخیر، غیبت، موارد انضباطی و تخلف پوششی + مینیمایز پنل‌ها
├── teacher.php ‍ پنل معلم: پایه رشته کلاس + ثبت سریع تأخیر/غیبت/انضباطی/پوششی
├── export.php گزارش‌گیری + خروجی PDF/چاپ + CSV + فایل نمونه ورود گروهی
├── install.php نصب‌کننده خودکار (گام‌به‌گام) — پس از نصب حذف شود
├── logout.php خروج امن از سامانه
├── icons.php مجموعه آیکون‌های خطی SVG (بدون فایل تصویری خارجی)
├── assets/img/icons/ ۴۲ تصویر PNG سرمه‌ای (۶۴×۶۴) برای استفادهٔ دلخواه
├── assets/img/icons-white/ همان آیکون‌ها با رنگ سفید (پس‌زمینهٔ تیره)
├── .htaccess محافظت از فایل‌های حساس + سرآیندهای امنیتی
├── config.php پیکربندی پایگاه داده (خودکار ساخته می‌شود) 
├── honarestan_mysql.sql SQL Dump ساختار + داده اولیه (خودکار ساخته می‌شود)
├── router.php روتر آزمایشی سرور داخلی PHP (روی هاست واقعی لازم نیست)
├── README.md همین راهنما 
├── data/ پایگاه داده SQLite، کش تاریخ، فایل قفل نصب 
├── tests/ آزمون‌های خودکار توسعه‌دهنده (برای اجرای سایت لازم نیست)
└── docs/ (نمونه‌های ایستا + تصویرهای پیش/پس از اصلاحات در docs/round8/)
 └── sample-report.html نمونه برگه گزارش (برای آزمون چاپ A4 / PDF)
```

> **قانون معماری پروژه:** هر پنل در یک فایل PHP مستقل است و تمام **CSS، HTML و JavaScript به‌صورت Inline** داخل همان فایل قرار دارد؛ هیچ فایل خارجی CSS/JS وجود ندارد (تنها فونت وزیرمتن از CDN اختیاری بارگذاری می‌شود و در نبود اینترنت، فونت سیستمی جایگزین می‌شود).

### توضیح کوتاه هر فایل

| فایل | مسئولیت | نکات کلیدی |
|------|---------|------------|
| **`db.php`** | زیرساخت مشترک | ثابت‌های دامنه (پایه/رشته/پرمیشن)، `db()` اتصال PDO Singleton، توابع DAL (`q`, `rows`, `row`, `one`, `db_insert`, `db_update`, `db_delete`)، امنیت (CSRF، Sanitize، Rate Limit، `has_perm`)، **تقویم شمسی** (تبدیل دوطرفه، بازه تاریخ، روز هفته، اعداد فارسی)، خواندن فایل xlsx/CSV، تابع قالب `layout_head/layout_end` با CSS/JS مشترک |
| **`index.php`** | ورود + داشبورد | ورود با Rate Limiting و پیام‌های فارسی، کارت‌های آماری (کل دانش‌آموزان، غیبت امروز، تأخیر امروز، انضباط هفته، پوشش امروز)، نمودار ۷ روز اخیر، توزیع پایه/رشته، فهرست رکوردهای امروز (قابل مینیمایز)، رتبه‌بندی هفتگی، API داخلی `?action=stats&ajax=1` برای بروزرسانی زنده |
| **`admin.php`** | مدیریت دسترسی‌ها | افزودن/ویرایش/فعال‌سازی/حذف ادمین، پرمیشن‌ها، پریست‌های آماده (معلم/معاون/مسئول انضباط/**معاون ارشد**/**مدیر**)، **تنظیمات روزهای تعطیل هفتگی + اجازهٔ ثبت در تعطیل**، **ستون «ثبت‌های این هفته»** هر کاربر، فیلتر نقش، ماتریس پرمیشن‌ها، محافظت از ارتقای سطح دسترسی |
| **`students.php`** | دانش‌آموزان | سه روش افزودن (Excel/CSV/TXT/دستی)، جستجوی پیشرفته + فیلتر ترکیبی + مرتب‌سازی ستون + صفحه‌بندی، ویرایش و حذف، **انتخاب گروهی با تیک + نوار عملیات گروهی (ثبت تأخیر/غیبت/انضباط/پوشش، تغییر پایه، تغییر رشته، حذف)**، **تب عملیات گروهی بر اساس پایه/رشته**، خروجی CSV، گزارش خطای فایل آپلودی، جلوگیری از داده تکراری |
| **`records.php`** | ثبت موارد | **تب پنجم «ثبت گروهی» برای چند دانش‌آموز با فیلتر پایه/رشته + انتخاب همهٔ نتایج + ضد تکرار**، چهار تب مستقل (تأخیر/غیبت/انضباط/پوشش)، انتخاب دانش‌آموز با **جستجوی زنده AJAX**، ساعت خودکار + چیپ‌های سریع ساعت، تاریخ شمسی با تقویم داخلی، محاسبه خودکار روز هفته برای غیبت، نمایش رکوردهای «امروز» به‌صورت پیش‌فرض + انتخاب روز دیگر، مینیمایز هر پنل، حذف رکورد، **فیلتر دامنهٔ ثبت‌کننده (`?by`)**، **منع/هشدار ثبت در روز تعطیل**، نمایش «ثبت توسط: نام (نقش)» |
| **`assets/img/`** | تصویرهای آماده | خروجی PNG همان آیکون‌ها در دو رنگ (سرمه‌ای و سفید) — برای پاورپوینت، برگهٔ چاپی، طراحی یا استفادهٔ دستی در HTML؛ پیش‌نمایش کامل در `docs/icons-preview.html` |
| **`icons.php`** | مجموعه آیکون‌ها | ۴۲ آیکون خطی SVG با استایل یکسان؛ همهٔ پنل‌ها از `hs_icon()` در PHP و `HS.icon()` در JS استفاده می‌کنند — بدون فایل تصویری یا CDN |
| **`teacher.php`** | ‍ پنل معلم | کلاس‌محور: سه دکمهٔ پایه چیپ‌های رشتهٔ همان پایه (بدون کامپیوتر در دوازدهم) فهرست دانش‌آموزان کلاس با دکمه‌های **ثبت تأخیر / غیبت / انضباطی / پوششی**؛ پنجرهٔ ثبت با تاریخ شمسی، چیپ زنگ، ساعت ورود به کلاس و توضیحات؛ **ثبت غیبت اتوماتیک** (تاریخ و روز هفته خودکار + دلیل غیبت + کلاس/درس)؛ چند تأخیر در یک روز و بازگشایی خودکار پنجره پس از هر ثبت؛ نمایش سوابق همان کلاس با رعایت دامنهٔ دسترسی ثبت‌کننده |
| **`export.php`** | گزارش‌گیری | پنج حالت گزارش (**شامل گزارش تفکیکی ثبت‌کنندگان**)، **حذف خودکار ستون روزهای تعطیل**، **فیلتر ثبت‌کننده**، بازه تاریخ شمسی + بازه‌های آماده (امروز/دیروز/هفته/ماه/ماه قبل/۷ و ۳۰ روز)، سربرگ رسمی هنرستان، جدول روزبه‌روز با علامت‌گذاری، ستون جمع، جمع کل روزانه، خروجی CSV، دریافت فایل نمونه CSV/XLSX، چاپ A4 |
| **`install.php`** | نصب خودکار | بررسی پیش‌نیازها، فرم پیکربندی، ساخت ۱۱ جدول، درج پرمیشن‌ها، ساخت ادمین‌ها، داده نمونه، تولید `config.php` و `honarestan_mysql.sql` |

## ۷) سیستم دسترسی (RBAC) و پرمیشن‌ها

هر قابلیت سامانه یک **پرمیشن مستقل** است و برای هر ادمین جداگانه فعال/غیرفعال می‌شود:

| کلید پرمیشن | عنوان فارسی | کاربرد |

| `delete_student` | حذف دانش‌آموز | حذف تکی و گروهی (همراه با سوابق) |

| `register_discipline` | ثبت موارد انضباطی | ثبت/حذف مورد انضباطی با کسر |

**قواعد امنیتی RBAC:**

- **مدیر کل (Super Admin):** دسترسی کامل بدون نیاز به تخصیص پرمیشن؛ **تنها کاربری که می‌تواند ادمین جدید بسازد یا ادمین را حذف کند**.
- ادمین دارای `manage_admins` می‌تواند ادمین‌های معمولی را ویرایش کند، اما **نمی‌تواند** پرمیشن `manage_admins` بدهد یا حساب مدیر کل را تغییر دهد (جلوگیری از Privilege Escalation).
- حساب مدیر کل قابل حذف یا غیرفعال‌سازی نیست و کاربر نمی‌تواند حساب خودش را حذف/غیرفعال کند.
- در نبود پرمیشن، صفحهٔ **۴۰۳ فارسی** با نام پرمیشن موردنیاز نمایش داده می‌شود.

## ۹) ورود گروهی دانش‌آموزان (Excel / CSV / TXT)

**ترتیب ستون‌ها (در صورت نبود سربرگ):**

| ۱ | ۲ | ۳ | ۴ | ۵ | ۶ |
|---|---|---|---|---|---|
| نام | نام خانوادگی | پایه | رشته | تلفن پدر | تلفن مادر |

- **تشخیص خودکار سربرگ:** اگر سطر اول شامل عنوان‌هایی مانند «نام، نام خانوادگی، پایه، رشته، تلفن پدر، تلفن مادر» باشد، سامانه آن را تشخیص می‌دهد و ترتیب ستون‌ها آزاد است (نکته: عنوان‌های بلندتر اول تطبیق داده می‌شوند تا «نام خانوادگی» با «نام» اشتباه نشود).
- **فرمت‌های پذیرفته‌شده:** `xlsx` (خوانده‌شده با ZipArchive — بدون کتابخانه خارجی)، `csv`، `txt`، `tsv`. فایل‌های `xls` قدیمی (OLE) پشتیبانی نمی‌شوند؛ در Excel گزینهٔ **Save As xlsx** یا **CSV UTF-8** را انتخاب کنید.
- **اعتبارسنجی هر سطر:** نام/نام خانوادگی فارسی، پایه در {دهم، یازدهم، دوازدهم}، تطابق رشته با پایه، شمارهٔ تماس ۱۱ رقمی (`09xxxxxxxxx` با پذیرش ارقام فارسی و تبدیل `+98`).
- **گزارش پس از آپلود:** تعداد کل سطرها، افزوده‌شده، تکراری (نادیده‌گرفته‌شده) و سطرهای دارای خطا — با ذکر **شمارهٔ سطر و علت خطا**.
- **جلوگیری از تکرار:** بر اساس ترکیب «نام + نام خانوادگی + پایه + رشته».
- **فایل نمونه:** از صفحهٔ `export.php` دکمه‌های « فایل نمونه CSV» و « فایل نمونه Excel».

### خروجی گرفتن (نسخه ۱.۰.۱ — بازنویسی‌شده)

1. گزارش را بسازید (نوع، پایه، رشته، بازه، جهت کاغذ).
2. روی ** خروجی PDF / چاپ** بزنید:
 - اگر سامانه در تب معمولی مرورگر باز باشد پنجرهٔ چاپ همان صفحه باز می‌شود (نوار تنظیمات، منو و دکمه‌ها به‌صورت خودکار از چاپ حذف می‌شوند).
 - اگر داخل iframe/پیش‌نمایش باشد یا پاپ‌آپ مسدود باشد **برگهٔ چاپ در تب جدید** باز می‌شود و چاپ خودکار آغاز می‌گردد؛ در غیر این صورت پنجرهٔ راهنما با **لینک باز کردن** و **آدرس قابل کپی** نمایش داده می‌شود.
3. در پنجرهٔ چاپ، مقصد را روی **Save as PDF** بگذارید (نام پیشنهادی فایل در بالای برگه چاپ نمایش داده می‌شود).
4. جهت کاغذ: گزینهٔ «خودکار» برای بازه‌های بیشتر از ۱۴ روز، **افقی (Landscape)** و برای بقیه **عمودی (Portrait)** انتخاب می‌کند؛ به‌صورت دستی هم قابل انتخاب است.
5. میان‌بُرها: دکمهٔ شناور ** خروجی PDF** در پایین صفحه، لینک ** باز کردن برگه چاپ در تب جدید** و کلید **Ctrl+P**.
6. دکمهٔ ** خروجی CSV** همان جدول گزارش با BOM برای باز شدن صحیح در Excel.
7. نمونهٔ آمادهٔ برگه: `docs/sample-report.html` (برای آزمون سریع چاپ A4 بدون نیاز به ورود به سامانه).

> برای آزمون داخل پیش‌نمایش Workspace: دکمهٔ چاپ، برگه را در **تب جدید** باز می‌کند؛ چاپ خودکار در آن تب انجام می‌شود.

## نسخه ۱.۳.۳ — چیپ‌های زنگ، پیام موفقیت پنل معلم و اصلاح کامل حالت شب

سه اصلاح بر پایهٔ بازخورد کاربر (دو تصویر ارسالی از حالت شب + گزارشِ نبود پیام موفقیت در پنل معلم):

### ۱) چیپ‌های زنگ/ساعت در «ثبت موارد» بازطراحی شد

- پیش‌تر هر چیپ یک کادر کهربایی پررنگ بود که در حالت شب سنگین و نامرتب دیده می‌شد و چیپ «پاک کردن» هم‌شکلِ زنگ‌ها بود و با آن‌ها اشتباه می‌شد.
- اکنون ردیف چیپ‌ها **شبکه‌ای با عرض یکسان** است؛ همهٔ چیپ‌ها هم‌اندازه، متن‌ها یک‌خطی و مرتب‌اند و رنگ‌ها از متغیرهای تم می‌آیند تا در حالت شب هم خوانا بمانند.
- **حالت انتخاب‌شده:** با کلیک روی هر زنگ، همان چیپ با قاب کهربایی روشن می‌شود (در هر ردیف فقط یک چیپ فعال می‌ماند) و نام زنگ زیر فیلد ساعت نمایش داده می‌شود.
- چیپ **«پاک کردن»** با خط‌چین و رنگ کم‌رنگ از زنگ‌ها جدا شد (قرمز فقط در حالت هاور).
- متن راهنمای ردیف چیپ‌ها و یادداشت «روز تعطیل» به‌جای `textContent` با `innerHTML` نوشته می‌شوند تا آیکون‌ها به‌صورت تصویر دیده شوند (نه کد SVG).

### ۲) پیام موفقیت در پنل معلم + پایانِ باز شدن خودکار پنجره

- علت مشکل: پس از ثبت غیبت، سرور پیام «غیبت … ثبت شد» را می‌ساخت و مرورگر را دوباره با `open=absence&sid=…` برمی‌گرداند؛ پنجرهٔ ثبت روی همان پیام می‌افتاد و به‌نظر می‌رسید هیچ اتفاقی نیفتاده است.
- اکنون پس از ثبت موفق پنجره **بسته می‌ماند** و پیام موفقیت هم‌زمان در سه جا دیده می‌شود: کادر سبز بالای صفحه، **توست شناور** (با `z-index` بالاتر از پنجره‌های مودال، پس روی پنجرهٔ باز هم دیده می‌شود) و کارت «ثبت … انجام شد» با دکمهٔ **«ثبت مورد بعدی برای همین دانش‌آموز»**.
- در فرم غیبت گزینهٔ اختیاری **«پنجره بعد از ثبت باز بماند»** اضافه شد (مثل تأخیر، برای ثبت سریع چند مورد). با فعال بودن آن، پنجره باز می‌ماند و توست «ثبت شد؛ می‌توانید مورد بعدی را همین‌جا ثبت کنید» نمایش داده می‌شود.
- همهٔ پیام‌های سرور (موفقیت/خطا/هشدار) در تمام پنل‌ها به‌صورت توست شناور هم نشان داده می‌شوند.

### ۳) رفع نمایش «کد SVG» روی صفحه (باگ آیکون‌ها)

- در چند نقطه، خروجی `hs_icon()` داخل متنِ escape‌شده (پیام فلش، `textContent`، `alert`) قرار می‌گرفت و کاربر به‌جای آیکون، متن `<svg …>` می‌دید. اکنون **هیچ آیکونی از `e()` یا `textContent` عبور نمی‌کند**؛ نام آیکون در داده ذخیره و در HTML مستقیماً رندر می‌شود و برای متن‌های پویا تابع کمکی `HS.esc()` اضافه شد.
- بازرسی خودکار در ۱۰ صفحه × ۲ تم: **۰ مورد** متن SVG خام، **۰ آیکون ناقص**، **۰ ایموجی**، **۰ خطای جاوااسکریپت**.

### ۴) اصلاح کامل حالت شب (تضاد رنگ‌ها)

- ریشهٔ مشکل: متغیر `--navy` در تم شب روشن می‌شود و جاهایی که از آن **به‌عنوان پس‌زمینه** استفاده می‌شد (نوار کناری، سربرگ جدول‌ها، دکمهٔ اصلی، کارت سرمه‌ای پنل معلم، بَج‌ها) متن سفید روی پس‌زمینهٔ روشن می‌افتاد و ناخوانا می‌شد.
- دو متغیر تازه `--navy-bg` و `--navy-bg-2` برای «سطوح سرمه‌ایِ همیشه تیره» اضافه شد و همهٔ آن پس‌زمینه‌ها به آن‌ها منتقل شدند (نوار کناری، هدر جدول‌ها، دکمهٔ اصلی، تب فعال، صفحه‌بندی، نوار دامنه نمایش، بَج روز/سهم، کارت بالای پنل معلم، صفحهٔ ورود و نصب).
- تضاد متن‌های آبی/کهربایی روی سطح ملایم (`.who-chip`، `.chip`، بَج‌های آبی/کهربایی، یادداشت تعطیلی، `print-note`) اصلاح شد و دکمه‌های رنگی در تم شب کمی تیره‌تر شدند تا متن سفیدشان خوانا بماند.
- عنوان «پنل معلم» که روی کارت سرمه‌ای، رنگ سرمه‌ای می‌گرفت (و در تم روز نامرئی بود) سفید شد.
- نتیجهٔ اندازه‌گیری خودکار تضاد (WCAG) روی ۱۰ صفحه: **حالت شب ۰ مورد کم‌تضاد**؛ حالت روز بدون تغییر محسوس.

> آزمون رگرسیون این نسخه: **۱۲۳ ✅ / ۰ ❌** (jsdom برای پنل معلم، تب‌های ثبت موارد، لودر مقاوم، عملیات گروهی دانش‌آموزان و پنل ثبت گروهی) — همراه با بازرسی بصری Chromium در هر دو تم.

### ۵) تکمیل پیام‌های «ثبت» و حذف آخرین موارد نمایش کد SVG

- متن **همهٔ** پیام‌های موفقیت پنل معلم و صفحهٔ ثبت موارد (تأخیر، غیبت، انضباطی، پوششی، ثبت گروهی و حذف رکورد) به شکل «<b>… با موفقیت ثبت شد — نام دانش‌آموز، تاریخ</b>» یکدست شد تا نتیجهٔ ثبت فوراً دیده شود.
- آخرین نقطه‌ای که آیکون می‌توانست به‌صورت کد نمایش داده شود (انتخاب فایل در دراپ‌زون ورود گروهی، `textContent`) هم به `innerHTML` با `HS.esc()` تغییر کرد؛ نتیجهٔ بازرسی تعاملی (کلیک روی همهٔ چیپ‌ها، تب‌ها، مودال‌ها، انتخاب دانش‌آموز، انتخاب فایل) در هر دو تم: **۰ مورد کد SVG در متن یا در title/placeholder**.
- تصویرهای پیش/پس این دور در `docs/round8/` (از جمله `evidence-round8b.png`).

## نسخه ۱.۳.۲ — آیکون‌گذاری کامل، تلفن اختیاری و اصلاح حالت شب

سه اصلاح بر پایهٔ بازخورد کاربر:

### ۱) همهٔ بخش‌ها آیکون دارند

- کارت‌های آماری داشبورد و صفحهٔ ثبت موارد (کل دانش‌آموزان، غیبت‌های امروز، تأخیرهای امروز، موارد انضباطی هفتهٔ جاری، تخلف پوششی) هر کدام آیکون اختصاصی گرفتند.
- سرصفحهٔ بخش‌های صفحهٔ ثبت موارد و کارت‌های پایه/رشته در پنل معلم آیکون‌دار شدند.
- در صفحهٔ دانش‌آموزان: دکمه‌های ردیف (ویرایش، ثبت مورد جدید، حذف)، تب‌ها (فهرست، افزودن دستی، آپلود، عملیات گروهی)، دکمهٔ «اعمال فیلتر»، «پاک کردن فرم»، «ثبت دانش‌آموز»، «ذخیره تغییرات»، «شروع ورود گروهی»، «معکوس» و «لغو انتخاب» همگی آیکون گرفتند.
- پیام‌های راهنما (کادرهای اطلاعات/هشدار/خطا) و پیام‌های شناور (توست) هم آیکون برداری دارند.
- آیکون تازه `copy` (کپی) برای دکمه‌های «درج» حساب‌های نمونه اضافه شد؛ مجموعه اکنون **۴۲ آیکون** است و تصویرهای PNG آن نیز در `assets/img/` به‌روز شد.
- هیچ ظرف آیکونِ خالی در سامانه باقی نمانده است (بررسی خودکار شد).

### ۲) شمارهٔ تلفن دیگر الزامی نیست

- در «افزودن دستی»، «ویرایش دانش‌آموز» و «ورود گروهی»، شمارهٔ تلفن پدر و مادر **اختیاری** است و برچسب «(اختیاری)» دارند.
- اگر فیلد خالی بماند، مقدار خالی ذخیره می‌شود؛ ولی اگر پر شود، سامانه همان اعتبارسنجی قبلی را انجام می‌دهد (۱۱ رقم، شروع با ۰۹، پذیرش ارقام فارسی).
- پیام خطای نامعتبر بودن شماره به «یا آن را خالی بگذارید» اصلاح شد؛ در ورود گروهی هم ستون‌های تلفن اختیاری‌اند.

### ۳) خوانایی حالت شب (تم تیره)

- متغیر رنگ سرصفحه‌ها در تم شب اصلاح شد؛ کارت‌های پایه/رشتهٔ پنل معلم، کارت‌های آماری، سرصفحهٔ جدول‌ها و دکمه‌ها اکنون متن روشن و خوانا دارند.
- برای همهٔ عناصر رنگی (کادر اطلاعات/هشدار/خطا، برچسب‌ها، دارت‌ها، جستجو، چیپ زنگ‌ها، دکمهٔ حذف، کارت توضیح خودکار و نوار روز) نسخهٔ شب تعریف شد.
- رنگ‌های تیره‌ای که به‌صورت درون‌خطی (style) در پنل‌ها بودند، در تم شب به رنگ روشن تبدیل می‌شوند؛ در نتیجه هیچ متنی روی زمینهٔ تیره محو نمی‌شود.
- صحت ظاهر در هر دو تم با مرورگر واقعی (Chromium) روی صفحه‌های داشبورد، دانش‌آموزان، ثبت موارد، گزارش‌ها، مدیریت ادمین‌ها و پنل معلم آزموده و بی‌خطا تأیید شد.

## نسخه ۱.۳.۱ — آیکون‌های برداری + ثبت و حذف غیبت در پنل معلم

این نسخه سه تغییر را بر اساس بازخورد کاربردی کاربر اعمال می‌کند: **حذف کامل ایموجی‌ها از سراسر سامانه** و جایگزینی آن‌ها با یک مجموعه آیکون برداری آماده، **ساده‌سازی ثبت غیبت در پنل معلم** (توضیحات را خودِ سامانه می‌نویسد) و **امکان حذف غیبت/رکورد اشتباه** توسط همان معلم.

### ۱) مجموعه آیکون برداری (بدون ایموجی)

- فایل تازه **`icons.php`** شامل **۴۲ آیکون خطی SVG** با استایل یکسان (خطی، ضخامت ۱.۷، رنگ هم‌رنگ متن): خانه، مدرسه، دانش‌آموز، معلم، زنگ، تقویم، تأخیر، غیبت، انضباطی، پوششی، حذف، ویرایش، جستجو، چاپ، قفل، سپر، نمودار، ستاره، هشدار، اطلاعات و…
- همهٔ آیکون‌ها **درون خودِ صفحه** رندر می‌شوند؛ نه فایل تصویری خارجی لازم است، نه CDN و نه فونت آیکونی.
- دو تابع کمکی در دسترس همهٔ ماژول‌ها:
  - در PHP: `hs_icon('trash', 18)` — خروجی `<svg class="hs-i">`
  - در JavaScript: `HS.icon('trash', 18)`
- همان آیکون‌ها به‌صورت **تصویر PNG آماده** هم در `assets/img/icons/` (سرمه‌ای) و `assets/img/icons-white/` (سفید) ذخیره شده‌اند؛ پیش‌نمایش تصویری: `docs/icons-preview.html`.
- ایموجی‌ها از **همهٔ فایل‌ها** (db.php، index، students، records، teacher، admin، export، install و README) حذف شدند. تنها کاراکترهای تایپوگرافی لازم مانند `‹ ›`، `→` در توضیحات کد و فلش مرتب‌سازی جدول باقی مانده‌اند.

### ۲) ثبت غیبت در پنل معلم: دکمه بزن، توضیحات را سامانه می‌نویسد

- فیلد «دلیل غیبت» و فهرست پیشنهادها از پنجرهٔ غیبت **کاملاً حذف شد**؛ معلم چیزی تایپ نمی‌کند.
- معلم فقط **کلاس/درس** و **زنگ (اختیاری)** را انتخاب می‌کند و یک‌بار «ثبت غیبت» را می‌زند.
- سامانه خودش متن توضیحات را می‌سازد: «غیبت — ثبت توسط <نام معلم> (کلاس/درس انتخابی)» و ساعت/تاریخ/روز هفته را خودکار پر می‌کند.
- کارت سبزرنگ «توضیحات غیبت نیازی به نوشتن ندارد» در همان پنجره، این رفتار را به معلم توضیح می‌دهد.
- در `records.php` (نقش‌های مدیر/معاون/ناظم) فیلد دلیل غیبت مانند قبل باقی است، چون آن صفحه محل ثبت کامل و مستند است.

### ۳) حذف رکورد اشتباه (غیبت و بقیهٔ موارد)

- در بخش «سوابق روز» پنل معلم، کنار هر رکورد یک دکمهٔ **حذف** (آیکون سطل زباله) اضافه شد.
- پنجرهٔ تأیید، نام دانش‌آموز، نوع رکورد و تاریخ/زنگ را نشان می‌دهد تا حذف اشتباهی رخ ندهد.
- **قاعده‌های امنیتی حذف:**
  - هر معلم فقط رکوردهایی را می‌تواند حذف کند که **خودش** ثبت کرده است؛
  - مدیر کل و دارندگان پرمیشن «مشاهده سوابق همه کاربران» همهٔ رکوردها را می‌توانند حذف کنند؛
  - حذف فقط برای کلاسی که همین حالا در پنل انتخاب شده و با CSRF معتبر انجام می‌شود؛
  - عملیات حذف در گزارش رویدادها (`activity_log`) ثبت می‌شود.
- حذف برای هر چهار نوع رکورد (تأخیر، غیبت، انضباطی، پوششی) کار می‌کند و پرمیشن ثبت همان نوع را لازم دارد.

### ۴) ناوبری روز در پنل معلم

- بالای بخش سوابق کلاس، نوار **«روز قبل / روز بعد / بازگشت به امروز»** اضافه شد (پارامتر `?jdate=`)، بنابراین معلم می‌تواند غیبت اشتباهی را که **دیروز** ثبت کرده هم پیدا و حذف کند.
- فهرست کلاس همیشه بر اساس روز نمایش فیلتر می‌شود و نشان می‌دهد «در حال مشاهدهٔ روزی غیر از امروز».

| فایل تازه | `icons.php` (۴۲ آیکون) + ضمیمهٔ دو تابع `hs_icon()` و `hs_icon_set()` |
| فایل‌های تغییر یافته | `db.php`، `teacher.php`، `index.php`، `records.php`، `students.php`، `admin.php`، `export.php`، `install.php`، `README.md` |

## نسخه ۱.۳.۰ — پنل معلم (کلاس‌محور) + جداسازی دسترسی معلم

### الف) ‍ پنل معلم — صفحهٔ مستقل `teacher.php`

معلم پس از ورود، از منوی «‍ پنل معلم (کلاس‌ها)» وارد پنل خودش می‌شود. مسیر کار در این پنل دقیقاً سه گام است:

1. **انتخاب پایه:** سه دکمهٔ بزرگ — **پایه دهم** / **پایه یازدهم** / **پایه دوازدهم** (روی هر دکمه تعداد دانش‌آموزان آن پایه نوشته شده است).
2. **انتخاب رشته:** با کلیک روی پایه، رشته‌های همان پایه به‌صورت چیپ نمایش داده می‌شوند
 ( در پایهٔ دوازدهم رشتهٔ **کامپیوتر** نمایش داده نمی‌شود — همان قانون دامنه). کنار هر رشته تعداد دانش‌آموزان آن کلاس آمده است.
3. **فهرست کلاس:** با انتخاب رشته، **همهٔ دانش‌آموزان آن کلاس** در جدولی نمایش داده می‌شوند و کنار هر دانش‌آموز دکمه‌های ثبت وجود دارد:

| دکمه | توضیح |
|------|-------|
| **ثبت تأخیر** | ساعت ورود به کلاس (با چیپ‌های زنگ) + توضیحات تأخیر — **چند تأخیر در یک روز مجاز است** |
| **ثبت غیبت** | **اتوماتیک:** تاریخ و روز هفته خودکار پر می‌شوند؛ معلم فقط **دلیل غیبت** را می‌نویسد و **کلاس/درس** و در صورت نیاز **زنگ** را انتخاب می‌کند و یک‌بار «ثبت غیبت» را می‌زند |
| **ثبت مورد انضباطی** | نوع مورد (فهرست آماده) + کسر نمره + توضیحات |
| **ثبت تخلف پوششی** | نوع تخلف (لباس/شلوار/هر دو/سایر) + توضیحات |

نکات کاربردی پنل:

- **هر ثبت = یک کلیک:** تاریخ پیش‌فرض روی امروز (یا آخرین روز کاری اگر امروز تعطیل باشد) تنظیم است و روز هفته خودکار محاسبه می‌شود.
- **چند تأخیر در یک روز:** پس از هر ثبت، پنجرهٔ تأخیر برای **همان دانش‌آموز** باز می‌ماند و پیام موفقیت نشان داده می‌شود؛ کافی است زنگ بعدی را بزنید و دوباره ثبت کنید. تنها ثبتِ دقیقاً تکراری (همان تاریخ + همان ساعت/زنگ) رد می‌شود و پیام فارسی می‌گوید در کدام زنگ ثبت شده است.
- **سوابق همان روز کلاس:** زیر جدول کلاس، تأخیرها و غیبت‌های همان کلاس برای روز مرجع نمایش داده می‌شوند (با رعایت دامنهٔ دسترسی: معلم سوابق خودش را می‌بیند، مدیر کل همه را).
- **نشان‌های وضعیت:** در ردیف هر دانش‌آموز، تعداد تأخیر امروز و وضعیت غیبت/انضباطی/پوششی با نشان‌های رنگی دیده می‌شود.
- **جستجوی داخل کلاس:** کادر جستجو فقط ردیف‌های همان کلاس را فیلتر می‌کند.
- **روز تعطیل:** اگر امروز پنجشنبه/جمعه باشد و مدیر کل اجازهٔ ثبت در تعطیل را نداده باشد، دکمه‌های ثبت غیرفعال می‌شوند، بنر هشدار نمایش داده می‌شود و سرور هم ثبت را با پیام فارسی رد می‌کند.
- دکمه‌های داخل پنل بر اساس پرمیشن‌های کاربر ساخته می‌شوند (مثلاً معلمی که فقط تأخیر و غیبت دارد، دکمه‌های انضباطی/پوششی را نمی‌بیند).

### ب) جداسازی دسترسی معلم: «کلاس‌ها» بله، «فهرست کامل دانش‌آموزان» نه

- پرمیشن جدید **`teacher_panel` — «‍ پنل معلم (کلاس‌ها)»** به فهرست پرمیشن‌ها اضافه شد و در صفحهٔ **ساخت/ویرایش ادمین** قابل تیک زدن است
 (گروه جدید «پنل معلم» + دکمهٔ آمادهٔ «‍ پیش‌فرض معلم» که این پرمیشن را همراه ثبت تأخیر و غیبت فعال می‌کند).
- معلم به صفحهٔ **«دانش‌آموزان»** (فهرست، افزودن، ویرایش، حذف و ورود گروهی) دسترسی **ندارد**؛ اگر آدرس را دستی هم وارد کند، پیام «دسترسی غیرمجاز» می‌گیرد.
- تب **« ثبت گروهی»** در صفحهٔ ثبت موارد هم فقط برای کاربرانی است که پرمیشن «مشاهده دانش‌آموزان» دارند؛ معلم‌ها کلاس خود را از پنل معلم ثبت می‌کنند.
- هنگام به‌روزرسانی به این نسخه، حساب‌های با نقش «معلم» **یک‌بار** به‌صورت خودکار از «مشاهدهٔ همهٔ دانش‌آموزان» به «پنل معلم (کلاس‌ها)» منتقل می‌شوند (دسترسی‌های تأخیر/غیبت‌شان حفظ می‌شود). مدیر کل هر زمان می‌تواند این تنظیم را در `admin.php` تغییر دهد.
- سایر نقش‌ها دست‌نخورده ماندند: هر کاربر (معاون، مسئول انضباط، ناظر ارشد، مدیر) در صورت نیاز می‌تواند این پرمیشن را بگیرد و از همان پنل کلاس‌محور استفاده کند.

### ج) تکمیل فیلدهای غیبت (دلیل • کلاس/درس • زنگ)

برای اینکه «ثبت غیبت اتوماتیک» اطلاعات کامل داشته باشد، دو ستون تازه به جدول `absences` اضافه شد
(`lesson` کلاس/درس و `time` زنگ) و در **هر دو جا** قابل ثبت است: پنل معلم و فرم ثبت غیبت در `records.php`
(در فهرست غیبت‌ها هم نمایش داده می‌شوند: «دلیل: … — کلاس/درس: … — زنگ: …»).

> این ستون‌ها در نصب‌های موجود به‌صورت **خودکار** ساخته می‌شوند (بدون نیاز به نصب مجدد یا حذف داده‌ها)؛ فایل `honarestan_mysql.sql` و نصب‌کننده هم برای نصب تازه به‌روزرسانی شده‌اند.

## نسخه ۱.۲.۱ — زنگ‌های تأخیر (چند تأخیر در یک روز) + لودر مقاوم

### الف) زنگ‌های تأخیر — **چند تأخیر در یک روز مجاز است**

قاعدهٔ قبلی («برای هر دانش‌آموز در هر روز فقط یک تأخیر») برداشته شد. حالا دانش‌آموزی که صبح زنگ اول و بعد زنگ سوم دیر می‌رسد، **هر دو تأخیر جداگانه ثبت می‌شوند**:

- در فرم ثبت تأخیر (و در پنل « ثبت گروهی») کنار فیلد ساعت، چهار **چیپ زنگ** آمده است:

 | زنگ | ساعت |
 |-----|------|
 | زنگ اول | ۰۷:۴۵ |
 | زنگ دوم | ۰۸:۳۵ |
 | زنگ سوم | ۰۹:۴۵ |
 | زنگ چهارم | ۱۰:۳۵ |

 با کلیک روی هر چیپ، همان ساعت در فیلد ساعت قرار می‌گیرد و نام زنگ زیر فرم نمایش داده می‌شود. اگر ساعت موردنظر زنگ‌های بالا نباشد، می‌توانید ساعت را دستی (مثل `11:10`) وارد کنید.
- **تنها ثبت رد می‌شود اگر عیناً تکراری باشد:** همان دانش‌آموز + همان تاریخ + **همان ساعت/زنگ**. پیام خطا می‌گوید در کدام زنگ ثبت شده است و پیشنهاد می‌کند زنگ دیگری را انتخاب کنید.
- در فهرست تأخیرها، هر رکورد با برچسب زنگ دیده می‌شود: ` زنگ اول — ۰۷:۴۵`.
- اگر دانش‌آموزی در یک روز بیش از یک تأخیر داشته باشد، پس از ثبت، یک پیام اطلاعاتی نمایش داده می‌شود: «این دانش‌آموز در این روز N تأخیر (در N زنگ مختلف) دارد.»
- در « ثبت گروهی» با نوع «تأخیر»، یک **زنگ مشترک** برای همهٔ دانش‌آموزان انتخاب‌شده ثبت می‌شود؛ اگر برای بعضی از آن‌ها همان زنگ قبلاً ثبت شده باشد، آن‌ها **رد می‌شوند** و نام‌شان در پیام گزارش می‌آید (بقیه ثبت می‌شوند).
- **سفارشی‌سازی ساعت زنگ‌ها:** در جدول `settings` کلید `bells` را با این قالب تنظیم کنید:
 `07:45=زنگ اول,08:35=زنگ دوم,09:45=زنگ سوم,10:35=زنگ چهارم`
 (پیش‌فرض دقیقاً همین مقدار است؛ ترتیب و تعداد زنگ‌ها آزاد است و نام‌ها فارسی نمایش داده می‌شوند.)

### ب) لودر «در حال پردازش…» دیگر روی صفحه گیر نمی‌کند

- اگر درخواستی کند باشد، **پس از ۴ ثانیه** زیر پیام، راهنما و دکمهٔ **« بستن این پیام»** اضافه می‌شود؛ با کلیک روی آن (یا کلیک روی پس‌زمینهٔ تیره) لودر بسته می‌شود.
- اگر پاسخ در **۴۵ ثانیه** نرسد، لودر **خودکار** بسته می‌شود؛ همچنین با برگشتن به صفحه از حافظهٔ مرورگر (`pageshow`) لودر پاک می‌شود.
- ارسال‌هایی که با **اعتبارسنجی، پنجرهٔ تأیید یا قاعدهٔ روز تعطیل** لغو می‌شوند، دیگر لودر را باز نمی‌کنند (قبلاً همین باعث گیرکردن «در حال پردازش…» می‌شد).
- اگر روی لودر باز، پیام خطا/هشدار صادر شود، لودر به‌صورت خودکار بسته می‌شود.
- عملیات کند (حذف، حذف گروهی، عملیات گروهی، تغییر روز در صفحهٔ ثبت موارد و ساخت خروجی CSV) هم لودر مخصوص خودشان را با متن گویا نشان می‌دهند.

### آزمون‌های نسخهٔ ۱.۲.۱ (همه PASS)

 تکرار عیناً همان زنگ: پیام «… (زنگ سوم) قبلاً ثبت شده است؛ اگر زنگ دیگری بوده…» و ثبت نشد

## نسخه ۱.۲.۰ — عملیات گروهی روی دانش‌آموزان

در این نسخه می‌توانید چند دانش‌آموز را با هم انتخاب کنید و برای همه، یک‌جا عملیات انجام دهید:
**ثبت تأخیر / غیبت / مورد انضباطی / تخلف پوششی، تغییر پایه، تغییر رشته و حذف گروهی**.

### ۱) انتخاب گروهی در فهرست دانش‌آموزان

- ستون تیک در ابتدای جدول + چک‌باکس **«انتخاب همه»** در سربرگ (فقط ردیف‌های صفحهٔ جاری).
- نوار آبی **«عملیات گروهی»** بالای جدول که تعداد انتخاب‌شده را زنده نشان می‌دهد و شامل این عملیات است:

| عملیات | توضیح | پرمیشن لازم |
|--------|--------|--------------|
| ثبت تأخیر برای انتخاب‌شده‌ها | انتقال به تب «ثبت گروهی» با دانش‌آموزان پیش‌انتخاب‌شده | `register_delay` |
| ثبت غیبت برای انتخاب‌شده‌ها | همان مسیر | `register_absence` |
| مورد انضباطی / تخلف پوششی | همان مسیر | `register_discipline` / `register_dress` |
| تغییر پایهٔ انتخاب‌شده‌ها | تغییر پایه (و در صورت تمایل، رشته) همهٔ موارد تیک‌خورده | `edit_student` |
| تغییر رشتهٔ انتخاب‌شده‌ها | فقط رشته‌های مجاز هر پایه در فهرست می‌آید | `edit_student` |
| حذف انتخاب‌شده‌ها | حذف دانش‌آموز + همهٔ سوابقش، همراه با پنجرهٔ تأیید | `delete_student` |

پیش از اجرا، یک پنجرهٔ تأیید با **نام دانش‌آموزان** نمایش داده می‌شود.

### ۲) تب « ثبت گروهی» در صفحهٔ ثبت موارد

- چهار نوع مورد: **تأخیر** (ساعت)، **غیبت**، **مورد انضباطی** (نوع + کسر)، **تخلف پوششی** (نوع).
- انتخاب دانش‌آموزان با سه ابزار: **فیلتر پایه**، **فیلتر رشته** و **جستجوی نام** + دکمه‌های
 « انتخاب همهٔ نتایج فیلتر»، « معکوس» و « لغو انتخاب».
- **ضد تکرار:** هر دانش‌آموزی که در همان روز و همان نوع ثبت شده باشد، خودکار رد می‌شود و در پایان
 گزارش می‌شود (مثال: «۲ مورد قبلاً در همین روز ثبت شده بود و رد شد: علی رضایی، محمد احمدی»).
- **روز تعطیل:** اگر تاریخ انتخابی پنجشنبه/جمعه باشد، ثبت گروهی با پیام فارسی رد می‌شود (مگر مدیر اجازه داده باشد).
- سقف هر عملیات ۴۰۰ دانش‌آموز است و همهٔ ثبت‌ها با نام همان کاربر (`created_by`) ذخیره می‌شوند،
 پس **تفکیک سوابق** و قواعد نسخه ۱.۱.۰ برقرار می‌ماند.

### ۳) عملیات گروهی بر اساس فیلتر (تب « عملیات گروهی» در دانش‌آموزان)

| عملیات | مثال |
|--------|------|
| تغییر پایهٔ گروهی | همهٔ «دهم» «یازدهم» (یا «دهم مکانیک» «یازدهم مکانیک») |
| تغییر رشتهٔ گروهی | همهٔ «یازدهم مکانیک» «الکتروتکنیک» |
| حذف گروهی | حذف همهٔ دانش‌آموزان یک پایه/رشته (با هشدار و تأیید) |

### ۴) رعایت قانون رشته (کامپیوتر فقط دهم و یازدهم)

- در تغییر گروهی رشته، فهرست رشته‌ها **به‌صورت پویا بر پایهٔ ردیف‌های انتخاب‌شده** ساخته می‌شود؛ اگر چند پایه انتخاب شده باشند،
 فقط **رشته‌های مشترک** نمایش داده می‌شود.
- اگر پایه به **دوازدهم** تغییر کند و رشتهٔ دانش‌آموز «کامپیوتر» باشد، آن دانش‌آموز تغییر نمی‌کند و در گزارش خطا نامش می‌آید:
 «۲ مورد تغییر نکرد: … (رشته کامپیوتر در پایه دوازدهم مجاز نیست)».
- در سرور هم مستقل بررسی می‌شود؛ حتی با دست‌کاری فرم، رشته/پایهٔ نامعتبر ذخیره نمی‌شود.

> همهٔ عملیات گروهی در جدول `activity_log` ثبت می‌شود (تعداد، پایه/رشتهٔ مبدأ و مقصد).

## نسخه ۱.۱.۰ — روزهای تعطیل + تفکیک سوابق ثبت‌کنندگان

در این نسخه دو خواستهٔ جدید مدرسه پیاده‌سازی شد: **پنجشنبه و جمعه هیچ‌جای سامانه حساب نمی‌شود** و
**سوابق ادمین‌ها، معاونان و معلمان از هم جدا است؛ مدیر کل می‌تواند همه را ببیند**.

### الف) پنجشنبه و جمعه «تعطیل» است و شمرده نمی‌شود

| بخش سامانه | رفتار در روز تعطیل |
|-------------|----------------------|
| کارت‌های آماری داشبورد | آمار روی **آخرین روز کاری** محاسبه می‌شود (برچسب: «آخرین روز کاری — ۱۴۰۵/۰۷/۲۲ (چهارشنبه)») |
| نمودار هفته | ستون روزهای تعطیل ساخته نمی‌شود؛ هفتهٔ کاری = شنبه تا چهارشنبه |
| رتبه‌بندی هفتگی | جمع موارد تنها روی روزهای کاری هفته |
| تقویم شمسی (Date Picker) | روزهای تعطیل با رنگ قرمز و **خط‌خورده** نشان داده می‌شوند و انتخاب‌شان هشدار می‌دهد |
| فرم‌های ثبت تأخیر/غیبت/انضباط/پوشش | زیر فیلد تاریخ، یک **یادداشت قرمز** نمایش داده می‌شود و **ارسال فرم در سمت مرورگر سد می‌شود** (سمت سرور هم مستقل بررسی می‌شود و پیام فارسی برمی‌گرداند) |
| صفحهٔ ثبت موارد | اگر خودِ امروز تعطیل باشد، تاریخ پیش‌فرض به‌طور خودکار روی **آخرین روز کاری** تنظیم می‌شود |
| دکمه‌های ناوبری روز (‹ ›) | با هر کلیک، **روزهای تعطیل رد می‌شوند** و به نزدیک‌ترین روز کاری می‌رود (مثال: از چهارشنبه، دکمهٔ «روز بعد» به شنبه می‌پرد) |
| دکمهٔ «امروز» | اگر امروز تعطیل باشد، برچسب آن به **« آخرین روز کاری (تاریخ)»** تغییر می‌کند و همان روز کاری را نمایش می‌دهد |
| گزارش‌ها (`export.php`) | ستون پنجشنبه/جمعه **در کل جدول‌ها ساخته نمی‌شود**؛ شمار روزهای حذف‌شده بالای برگه گزارش می‌آید؛ «امروز/دیروز/هفته/ماه» هم به روز کاری منتقل می‌شود |
| داده‌های نمونه (`install.php`) | برای روزهای تعطیل هیچ دادهٔ نمونه‌ای ساخته نمی‌شود |
| داده‌های قدیمی | اگر رکورد قدیمی روی پنجشنبه/جمعه وجود داشته باشد، در آمار و گزارش‌ها **شمرده نمی‌شود** (داده حذف نشده، فقط نادیده گرفته می‌شود) |

**تنظیم روزهای تعطیل (مخصوص مدیر کل):** `admin.php` کارت ** تنظیمات روزهای تعطیل هفتگی**

- چک‌باکس هر روز هفته (پیش‌فرض: پنجشنبه و جمعه)؛ می‌توانید مثلاً «فقط جمعه» تعطیل بگیرید.
- سوئیچ **«اجازهٔ ثبت موارد در روزهای تعطیل»** برای مدرسه‌هایی که بعضی پنجشنبه‌ها دایر هستند.
 - خاموش (پیش‌فرض): ثبت در روز تعطیل با پیام فارسی زیر **رد می‌شود**:
 «روز پنج‌شنبه (۱۴۰۵/۰۷/۲۳) تعطیل است؛ ثبت مورد در این روز مجاز نیست…»
 - روشن: ثبت انجام می‌شود، اما پیام هشدار « … در آمار، نمودارها و گزارش‌ها شمرده نمی‌شود» نمایش داده می‌شود و آن مورد **در هیچ گزارشی نمی‌آید**.

### ب) سوابق هر ادمین/معاون/معلم جداست؛ مدیر همه را می‌بیند

هر رکورد (تأخیر، غیبت، انضباط، پوشش) با ستون `created_by` ذخیره می‌شود و نمایش/آمار بر پایهٔ آن **فیلتر** می‌گردد:

| کاربر | چه می‌بیند؟ |
|--------|--------------|
| معلم / معاون / مسئول انضباط | **فقط سوابقی که خودش ثبت کرده** (فهرست‌ها، کارت‌های آماری و گزارش‌ها) |
| مدیر کل (Super) | **همهٔ سوابق** + امکان فیلتر کردن بر اساس ثبت‌کننده |
| کاربر دارای پرمیشن `view_all_records` **+** `export_pdf` | مثل مدیر کل: همهٔ سوابق را می‌بیند (پیش‌فرض « معاون ارشد») |

**امکانات مدیر برای دیدن سوابق:**

1. **نوار دامنه (Scope Bar)** در بالای داشبورد و صفحهٔ ثبت موارد:
 `همهٔ ثبت‌کنندگان` / `فقط سوابق خودم` / نام هر معاون و معلم (لینک‌های `?by=all|me|<id>`).
 آدرس قابل اشتراک است؛ مثلاً `records.php?by=3&jdate=1405/07/22`.
2. **کارت «عملکرد ثبت‌کنندگان»** در داشبورد: جدول هفتگی هر کاربر با ستون‌های تأخیر / غیبت / انضباط / پوششی + لینک «مشاهده سوابق».
3. **گزارش تفکیکی ثبت‌کنندگان (PDF/CSV):** `export.php?mode=creators&quick=week`
 فهرست همهٔ ثبت‌کنندگان با نقش، تعداد هر نوع مورد و جمع کل + ردیف **جمع کل همه کاربران**.
 (دکمهٔ این گزارش هم روی کارت داشبورد و هم در جدول کاربران `admin.php` قرار دارد.)
4. **ستون «ثبت‌های این هفته»** در جدول کاربران `admin.php` + فیلتر بر اساس **نقش**.
5. در صفحهٔ ثبت موارد، زیر هر رکورد نوشته می‌شود: **«ثبت توسط: نام (نقش)»** — پس در نمای مدیر، مسئولیت هر ثبت مشخص است.
6. در گزارش‌های روزبه‌روز، فیلتر **«ثبت‌کننده»** به نوار ابزار گزارش اضافه شده است.

**پیش‌فرض‌های آمادهٔ نقش (در فرم ساخت/ویرایش ادمین):**

| دکمه | پرمیشن‌ها |
|------|------------|
| پیش‌فرض معلم | مشاهده دانش‌آموزان + ثبت تأخیر و غیبت |
| پیش‌فرض معاون | مشاهده/افزودن/ویرایش دانش‌آموز + هر چهار ثبت + خروجی PDF (**بدون** دیدن سوابق دیگران) |
| پیش‌فرض مسئول انضباط | مشاهده دانش‌آموزان + ثبت انضباط و پوشش + خروجی PDF |
| معاون ارشد — دیدن سوابق همه | معلم‌ها + `view_all_records` + `export_pdf` همهٔ سوابق را می‌بیند |
| مدیر / مسئول | همه‌چیز جز مدیریت ادمین‌ها |

> قانون فنی: پرمیشن `view_all_records` تنها وقتی اثر دارد که کاربر `export_pdf` هم داشته باشد؛
> بنابراین نمی‌توان بدون دسترسی گزارش‌گیری، سوابق دیگران را دید (جلوگیری از دسترسی ناخواسته).

**نمونهٔ خروجی:** `docs/sample-report.html` (گزارش روزبه‌روز بدون ستون تعطیل) و
`docs/sample-creators-report.html` (گزارش تفکیکی ثبت‌کنندگان).

**حساب نمونهٔ جدید برای آزمون تفکیک سوابق:** `supervisor` / `Supervisor@1404` (معاون ارشد — همهٔ سوابق را می‌بیند).
این حساب در حالت نصب با **دادهٔ نمونه** به‌طور خودکار ساخته می‌شود؛ اگر بدون دادهٔ نمونه نصب کنید، می‌توانید از دکمهٔ
« معاون ارشد — دیدن سوابق همه» در فرم ساخت ادمین استفاده کنید.

**آدرس‌های قابل استفادهٔ مدیر (مثال‌ها):**

```
records.php?by=me فهرست ثبت‌های خودم
records.php?by=3&jdate=1405/07/22 فهرست ثبت‌های کاربر شمارهٔ ۳ در یک روز مشخص
records.php همهٔ ثبت‌ها (مدیر) با نمایش «ثبت توسط»
index.php?by=3 داشبورد و آمار ثبت‌های کاربر ۳
export.php?mode=delay&quick=week&by=3 گزارش تأخیرهای ثبت‌شده توسط کاربر ۳
export.php?mode=creators&quick=month گزارش تفکیکی همهٔ ثبت‌کنندگان (PDF/CSV)
admin.php?role=deputy فهرست فقط معاونان + «ثبت‌های این هفته» هر نفر
```

## نسخه ۱.۰.۱ — گزارش رفع اشکال (دیباگ کامل)

در این نسخه، همه بخش‌های سامانه بازبینی و ۸ اشکال گزارش‌شده/کشف‌شده برطرف شد:

| # | مشکل گزارش‌شده | ریشه مشکل (علت فنی) | اصلاح انجام‌شده |
|---|-----------------|----------------------|------------------|
| ۱ | **دکمه منو در موبایل/تبلت منو را نشان نمی‌داد** | در `@media (max-width:1024px)` قانون `.sidebar{transform:translateX(110%)}` و `html[dir=rtl] .sidebar{...}` از نظر Specificity بر `.sidebar.open{transform:none}` غلبه می‌کردند، پس منو هرگز به صفحه برنمی‌گشت | قانون به `.sidebar.open{transform:translateX(0)!important}` تغییر یافت + مدیریت کامل JS: کلیک روی دکمه، کلیک روی پرده، کلید Escape، بستن خودکار پس از انتخاب گزینه، aria-expanded |
| ۲ | **بخش «افزودن دانش‌آموز» رشته قابل انتخاب نبود** | برچسب PHP (`<?= json_encode(...) ?>`) داخل بلوک nowdoc جاوااسکریپت نوشته شده بود؛ چون nowdoc اجرا نمی‌شود، خروجی به مرورگر `const FIELDS_BY_GRADE = <?= ...` می‌رسید **SyntaxError** کل اسکریپت صفحه (Dropdown داینامیک رشته، تأیید حذف، تب‌ها) از کار می‌افتاد | داده‌ها با Placeholder (`__FIELDS_BY_GRADE__`) تزریق می‌شوند؛ اسکریپت با `node --check` و jsdom آزمون شد |

| ۴ | **استایل برگه گزارش در صفحه اصلی گم شده بود** | با جدا شدن CSS چاپ به `$sheetCss`، این متغیر به `layout_head` پاس داده نشده بود | هر دو مجموعه استایل به صفحه پاس داده می‌شود |
| ۵ | **دکمه بازگشت وجود نداشت** | — | **در همه بخش‌ها**: دکمه « منوی اصلی» در نوار بالا، نوار مسیر (Breadcrumb) با « صفحه قبل»، نوار «بازگشت به منوی اصلی» در پایان هر صفحه و دکمه شناور « منوی اصلی» در موبایل |
| ۶ | **پذیرش نام حاوی عدد** | بازه `\x{0600}-\x{06FF}` در RegEx، ارقام فارسی (۰-۹) و عربی (٠-٩) را هم شامل می‌شد | بازه به `\x{0600}-\x{06EF}` اصلاح و بررسی جداگانه روی ارقام (فارسی/عربی/لاتین) اضافه شد — در **سرور و کلاینت** یکسان |
